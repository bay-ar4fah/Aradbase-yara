# Security Policy

## Supported Versions

The following versions of Aradbase-YARA are currently supported with security updates and rule maintenance.

| Version | Supported          |
| ------- | ------------------ |
| Latest  | :white_check_mark: |
| Legacy  | :x:                |

## Reporting a Vulnerability

If you discover a security vulnerability, detection bypass, false positive, false negative, or any issue affecting Aradbase-YARA detection rules, please report it responsibly.

For sensitive or undisclosed vulnerabilities, please avoid opening a public GitHub issue.

### Reporting Channels

- GitHub Security Advisories (preferred for sensitive findings)
- GitHub Issues (for non-sensitive problems or rule improvement discussions)

### What to Include

Please include as much relevant information as possible:

- Affected YARA rule(s)
- Description of the issue
- False positive or false negative evidence
- Relevant Indicators of Compromise (IOC), hashes, or sanitized samples
- Reproduction steps, if applicable

### Response Process

Security reports will be reviewed and validated by the maintainer.

Expected process:

| Stage | Estimated Time |
|--------|----------------|
| Initial acknowledgment | 3–7 days |
| Investigation & validation | Depends on complexity |
| Rule update / mitigation | As needed |

Accepted findings may result in rule improvements, detection tuning, or repository updates.

Reports that cannot be reproduced or fall outside the project scope may be declined.

Thank you for helping improve Aradbase-YARA and supporting responsible security research.
